A zombie process is one that has already finished running but still has an entry in the process table, because its parent hasn't yet called `wait` to collect its final exit status — it shows up in `ps` with a `Z` state, consuming essentially no resources but still technically present. An orphan process is the opposite situation: its parent process ended first, leaving the child still running with no parent to eventually `wait` on it.

Neither is usually a cause for alarm in small numbers — orphans get automatically adopted by `init` (or `systemd` as PID 1), which takes over responsibility for eventually cleaning them up, and a few short-lived zombies are completely normal. They become worth investigating only when a long-running process (commonly a server or daemon) accumulates many zombies over time, which usually points to a real bug: that process is spawning children and never calling `wait` on them.
