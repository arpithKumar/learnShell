`if` in shell scripting doesn't evaluate a boolean expression the way it would in most programming languages — it runs a command and branches based on that command's exit status: `0` means success (the `then` branch runs), anything else means failure. The square-bracket test `[ ... ]` that usually follows `if` is itself just a command (literally an alias for `test`), which is why `if [ -f file ]; then` and `if grep -q pattern file; then` are really the same mechanism applied to two different commands.

This explains a common point of confusion for newcomers: there's no special "if syntax" for testing values versus testing commands, just `if` always checking an exit status, with `[ ... ]` or `test` being the everyday tool for comparing strings, numbers, and file attributes. Quoting variables inside a test is important for the same reason quoting matters everywhere else — an empty or space-containing value can change how many arguments `[ ... ]` actually receives, breaking the comparison.
