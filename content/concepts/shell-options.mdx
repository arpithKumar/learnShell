Shell options, set with `set -OPTION`, change how the shell itself behaves rather than running a command. `set -e` makes the script exit immediately if any command fails (nonzero exit status) instead of continuing on regardless; `set -u` errors on any reference to an unset variable instead of silently treating it as empty; `set -o pipefail` makes a pipeline's exit status reflect any failing stage, not just the last one.

These three combined (`set -euo pipefail`) are commonly called bash's "strict mode" — a defensive habit for scripts where silently continuing after an error could do real damage. They're not a complete safety net, though: `set -e` in particular has several well-documented exceptions (commands inside an `if` condition, for instance, never trigger it), so it reduces certain classes of bugs without eliminating the need to actually check for errors where it matters.
