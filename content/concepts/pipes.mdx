A pipe (`|`) connects one command's standard output directly to the next command's standard input, without an intermediate file. This is the core idea behind Unix's "small tools, composed together" philosophy — `cat access.log | grep ERROR | wc -l` chains three simple, single-purpose commands into one pipeline that counts error lines, none of which individually needs to know how to do the others' job.

Each stage of a pipeline runs as its own process, and they generally run concurrently — data streams through as it's produced, rather than each command needing to finish completely before the next one starts. One subtlety worth knowing: by default, a pipeline's exit status is just the last command's, so a failure partway through (like `cat` failing to open a missing file) can go unnoticed unless `set -o pipefail` is enabled to make a failure anywhere in the chain count as a failure overall.
