Whether a shell session is "interactive" and whether it's a "login" shell are two separate, independent questions, not two names for the same thing. Interactive means a human is actively typing commands and seeing a prompt — a script run from cron isn't interactive, even though it might be running bash. Login means the shell is the first one started for a session, typically right after authenticating (SSH-ing in, or the very first terminal opened after logging into a desktop) — a new tab opened afterward usually is not a login shell, even though it's still interactive.

This distinction is exactly what determines which dotfiles get read: login shells read `.bash_profile`/`.profile`, while non-login interactive shells read `.bashrc`. Different operating systems and terminal emulators default differently here (notably, macOS's Terminal.app has historically treated new windows as login shells more often than common Linux setups do), which is a frequent source of "it works on my machine" dotfile confusion between platforms.
