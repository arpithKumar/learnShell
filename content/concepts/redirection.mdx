Redirection changes where a command's input or output goes, instead of the default terminal. `>` sends standard output (stream 1) to a file, overwriting it entirely; `>>` does the same but appends to the end instead. `<` does the reverse, feeding a file's contents in as a command's standard input.

Errors are a separate stream, standard error (stream 2), which is why a failing command's error message still shows up on your terminal even when you've redirected its normal output to a file with `>` — you'd need `2>` to redirect just the errors, or `2>&1` to merge them into the same destination as standard output. Mixing up `>` and `>>` is a common, occasionally destructive mistake, since `>` silently replaces a file's entire contents with no confirmation.
