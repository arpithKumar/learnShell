`set -x` turns on command tracing: the shell prints every command it's about to run, after all expansions (variables, globs, command substitution) have already happened, prefixed with `+`. This is the single most useful debugging tool in shell scripting, since it shows you what the script is *actually* executing rather than what you assumed the source code would produce.

`bash -x script.sh` applies the same tracing to a whole script run from the outside, without needing to edit the script to add `set -x` (and a matching `set +x` to turn it back off) internally. Customizing `PS4` (the prefix shown on each traced line, `+` by default) to include `$LINENO` is a small but genuinely useful addition for finding exactly where in a longer script something unexpected happened.
