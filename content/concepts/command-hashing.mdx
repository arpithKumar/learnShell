Once bash locates an external command by searching `$PATH`, it remembers that location in an internal hash table, so future calls to the same command name skip the search entirely and jump straight there. `hash` with no arguments shows what's currently cached; `hash -r` clears the whole table, forcing a fresh `$PATH` search the next time any command runs.

This caching is invisible almost all the time, but it surfaces as a genuinely confusing bug in one specific scenario: installing a new version of a command somewhere already on `$PATH` (replacing an old binary, or adding a new one earlier in the search order) doesn't always invalidate the stale cached entry automatically — the shell keeps confidently running the old, cached location until `hash -r` clears it out.
