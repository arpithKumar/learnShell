Beyond the commonly-used `${var:-default}`, parameter expansion has a small family of related operators for handling unset or empty variables, each answering a slightly different question. `-` and `:-` substitute a fallback value without changing the variable; `=` and `:=` do the same but also assign that fallback back into the variable; `+` and `:+` invert the logic, substituting a value only when the variable *is* set (or non-empty); and `?` and `:?` exit with an error message when the variable isn't set (or is empty).

The colon in each pair is the entire distinction: without it, the operator only triggers when the variable is completely unset; with it, the operator also triggers when the variable is set but empty. `${var:?message}` in particular is a genuinely useful validation pattern — placed near the top of a script, it turns a missing required variable into an immediate, clear failure instead of a confusing error much later when that empty value finally gets used.
