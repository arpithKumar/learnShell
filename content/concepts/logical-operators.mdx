`&&` and `||` chain commands based on the previous command's exit status: `cmd1 && cmd2` runs `cmd2` only if `cmd1` succeeded (exit status 0), while `cmd1 || cmd2` runs `cmd2` only if `cmd1` failed. Both are "short-circuiting" — the right-hand command may never run at all, which is exactly the intended behavior for guards like `command -v git >/dev/null || echo "git not found"`.

A common pattern, `cmd1 && cmd2 || cmd3`, reads like an if/else at a glance, but it isn't quite one: it's really just two independent chained checks evaluated left to right, so if `cmd2` itself happens to fail, `cmd3` runs too — not the mutually-exclusive branching an actual `if`/`else` would give you. For anything beyond the simplest guard, a real `if` statement is the more reliable and more readable choice.
