A subshell is a separate child process that inherits a copy of the current shell's variables and working directory, but any changes it makes — to variables, `cd`, or anything else — don't propagate back to the parent shell once it exits. Wrapping a command list in parentheses, like `(cd /tmp && ls)`, explicitly runs it in a subshell, so the `cd` doesn't affect your actual current directory once the parentheses close.

Command substitution (`$(...)`) and pipelines also run their components in subshells under most shells, which is exactly why a variable set inside a `while read line; do count=$((count+1)); done < file | cat` pipeline might mysteriously not be visible after the pipeline finishes — the loop ran in a subshell created for that pipeline stage, and its changes to `count` died with it. Recognizing "this ran in a subshell" is often the key to debugging a variable that "should" have changed but didn't.
