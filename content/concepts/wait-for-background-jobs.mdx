`wait` pauses a script until a background process finishes, and reports that process's exit status as its own — `wait "$pid"` (using a PID captured from `$!` right after backgrounding something) waits for that one specific job, while plain `wait` with no arguments waits for every currently-running background job to finish before continuing.

This is the standard way to launch several independent tasks concurrently and then synchronize before moving on — start them all with `&`, then `wait` once everything needs to have finished. Checking each one's individual success or failure needs a bit more care, though: capturing each job's PID separately and `wait`-ing on each one individually is necessary if the script needs to know specifically which jobs succeeded and which failed, since a bare `wait` only reports the last job's status.
