A file descriptor is a small integer a process uses internally to refer to an open input or output stream — `0` for standard input, `1` for standard output, `2` for standard error, by long-standing Unix convention, with any additional numbers available for a script to open more streams as needed. `exec 3> debug.log` opens a fourth stream (`3`) pointed at a log file, which can then be written to repeatedly with `>&3` without reopening the file each time.

Redirection syntax like `2>&1` is really just file-descriptor manipulation: "point file descriptor 2 at wherever file descriptor 1 currently points." This is also why the order in a chain like `command > file 2>&1` matters — `2>&1` has to come *after* `> file` redirects stdout, or stderr ends up pointed at the terminal instead of the file.
