Shell configuration exists at two layered levels: system-wide files (`/etc/profile`, `/etc/bash.bashrc`) that apply to every user on a machine by default, and per-user files (`~/.bash_profile`, `~/.bashrc`) that apply only to one account, typically read afterward so personal settings can override the system defaults. Both layers get combined with the login-vs-interactive distinction, which determines which specific file in each layer actually gets read for a given session.

In practice, a single login shell on a typical Linux system can chain through several files in sequence — the system-wide profile, then a personal profile, which commonly sources the personal `.bashrc` itself, which may in turn source a system-wide `.bashrc` too. This layering is invisible day to day, but it's exactly why "this setting works for me but not for a coworker on the same shared server" so often traces back to a difference somewhere in this chain rather than the setting itself being wrong.
