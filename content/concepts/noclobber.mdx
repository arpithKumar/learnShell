`set -o noclobber` (or the shorter `set -C`) changes `>` so it refuses to overwrite a file that already exists, failing with an error instead of silently destroying its previous contents. It's a small, genuinely useful interactive safety net against a common typo — redirecting into the wrong filename, or hitting up-arrow and re-running a command with `>` against a file you actually wanted to keep.

When an overwrite is intentional with `noclobber` turned on, `>|` explicitly forces it through regardless. The protection is narrow, though — it only covers plain `>` against an existing regular file; appending with `>>`, redirecting into special files like `/dev/null`, and unrelated destructive commands like `rm` are entirely unaffected by it.
