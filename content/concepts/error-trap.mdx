`trap 'commands' ERR` registers a handler that runs automatically whenever a command in the script fails, instead of needing to manually check `$?` after every single line. Combined with `$LINENO` inside the handler, this gives a basic but genuinely useful way to log roughly where a script broke, without instrumenting every command individually.

It shares the same notable exceptions `set -e` has — a failing command inside an `if` condition, or one side of an `&&`/`||` chain, won't trigger the `ERR` trap, since those are specifically excluded contexts. It's commonly paired with a separate `trap '...' EXIT` for cleanup that needs to run no matter how the script ends, whether that's a normal finish, an error, or an interrupt.
