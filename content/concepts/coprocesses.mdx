A coprocess, started with `coproc NAME { commands; }`, runs in the background with a bidirectional pipe connecting it to the current shell — unlike a normal pipeline, where data only flows one direction through a chain of commands. The shell can write to the coprocess's input and separately read from its output, both through file descriptors bash stores automatically in an array named after the coprocess.

This is useful for talking to a long-running helper process repeatedly — sending it one line, reading back a response, sending another — rather than starting a brand-new process for every single exchange. It's a comparatively advanced, less commonly needed feature; bash also only supports one active coprocess at a time by default, which is a real limitation if a script needs to juggle more than one simultaneously.
