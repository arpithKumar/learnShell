A `for` loop iterates over a fixed list of values — words typed directly, a glob expansion, or a command's output — running its body once per item, with the current item available as the loop variable. A `while` loop instead repeats as long as a test condition keeps succeeding, which is the right shape when you don't know in advance how many iterations you need, like reading a file line by line until it runs out.

The most common loop-related bug is iterating over unquoted command output or a glob that might match nothing or contain spaces — `for line in $(cat file)` silently splits on every space and newline, mangling any line with more than one word in it. The standard fix for "read a file line by line" specifically is `while read -r line; do ...; done < file`, which preserves each line exactly as written instead of word-splitting it.
