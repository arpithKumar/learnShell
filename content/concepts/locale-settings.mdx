Locale settings — `LANG`, `LC_ALL`, and several more specific `LC_*` variables — control how a shell and the programs it runs interpret things like sort order, number formatting, and character classification, based on regional and language conventions rather than purely the literal byte values involved. They're ordinary environment variables, but with system-wide reach into otherwise "deterministic-looking" commands like `sort` and string comparisons.

This is a genuine, recurring source of "works on my machine" bugs: the exact same `sort` command can order the same input differently depending on the active locale, since most locales sort case-insensitively and alphabetically by language convention, while the plain `C` locale sorts strictly by raw byte value instead. Explicitly setting `LC_ALL=C` at the top of a script that needs predictable, portable sorting or comparison behavior sidesteps this inconsistency entirely, regardless of whatever locale happens to be configured on the machine actually running it.
