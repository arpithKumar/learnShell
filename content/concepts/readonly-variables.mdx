`readonly NAME` (or equivalently `declare -r NAME`) locks a variable so any later attempt to reassign it fails with an error, for the remainder of that shell session or script. It's the shell's version of a constant — useful for values like a configuration URL or a fixed limit that should never accidentally change partway through a script.

Once set, there's no escape hatch: the lock can't be lifted, and even `unset` refuses to remove a readonly variable. This makes it a genuinely strong guarantee, not just a style convention — reaching for it on values that truly shouldn't change catches real bugs (an accidental reassignment somewhere later in a long script) the moment they happen, rather than letting them silently corrupt later behavior.
