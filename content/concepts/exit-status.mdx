After every command finishes, the shell stores a small number describing how it went, available immediately afterward as `$?`. By strong convention across virtually all Unix tools, `0` means success and any nonzero value means some kind of failure — though the specific nonzero number is often meaningful too (a particular tool might use `1` for "no matches" and `2` for "an actual error", for instance).

This exit status is exactly what `if`, `&&`, and `||` check — there's no separate "boolean" concept in shell scripting beyond a command's own exit status. It's also why error handling in shell scripts so often boils down to checking `$?` or wrapping a command in an `if`, rather than anything resembling a try/catch block from other languages.
