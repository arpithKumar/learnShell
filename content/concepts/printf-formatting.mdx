`printf` formats output using `%` specifiers borrowed directly from C's `printf` function: `%s` for a string, `%d` for an integer, `%f` for a floating-point number, with optional width and precision modifiers like `%03d` (zero-padded to 3 digits) or `%.2f` (2 decimal places). This gives far more precise control over output formatting than `echo`, which has no concept of padding, alignment, or fixed decimal precision at all.

A less obvious feature: if you supply more arguments than the format string has specifiers for, `printf` cycles back to the start of the format string and keeps consuming arguments — `printf "%s\n" a b c` prints all three on separate lines from one call. Because `echo`'s exact behavior (escape sequences, trailing newline handling) varies subtly between shells and even shell options, `printf` is generally the safer, more portable choice whenever output formatting needs to be exact.
