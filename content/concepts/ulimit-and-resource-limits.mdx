`ulimit` sets a ceiling on how much of a particular system resource the current shell, and every process it launches afterward, is allowed to consume — the number of open file descriptors (`-n`), maximum CPU time in seconds (`-t`), maximum memory (`-v`), and several others. Once set, these limits are inherited by child processes, making `ulimit` a practical way to contain a script or program that might otherwise consume more of a resource than intended.

There's a meaningful distinction between "soft" limits (the currently enforced ceiling, which an unprivileged process can usually lower further but not raise past the hard limit) and "hard" limits (the absolute ceiling, settable only with elevated privileges). This two-tier structure is what stops a misbehaving or malicious script from simply raising its own limits back up after they've been intentionally tightened.
