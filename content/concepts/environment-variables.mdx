Environment variables are the subset of a shell's variables that get passed down to every program it launches — `$PATH` (where to look for commands), `$HOME` (the current user's home directory), and `$USER` are common examples a shell sets up automatically. A plain variable assignment, by contrast, only exists inside the current shell; it has to be explicitly promoted with `export` before any child process can see it.

This distinction is the source of a recurring confusion: a script that reads a variable fine when run with `source` (which runs in the current shell) can suddenly see it as empty when run as `./script.sh` (a separate child process), simply because the variable was never exported. `env` and `printenv` both print the full current environment, which is the fastest way to confirm whether a given variable actually made it across that boundary.
