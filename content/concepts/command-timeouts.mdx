`timeout N command` runs a command but kills it automatically if it's still running after `N` seconds — a straightforward safeguard against a command that might hang indefinitely, whether due to a network issue, a stuck process, or input it's waiting on that will never arrive. The exit status `124` specifically signals "this was killed for taking too long," distinguishable from the command's own normal failure exit statuses.

By default, `timeout` sends `SIGTERM`, which a process can choose to ignore — `timeout -k` adds a second, harsher deadline after which it escalates to `SIGKILL` if the process still hasn't exited. Before `timeout` existed as its own coreutils command, achieving the same effect meant manually backgrounding a process, sleeping, then checking and killing it if still running — a noticeably more error-prone pattern than reaching for the dedicated command directly.
