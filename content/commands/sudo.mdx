`sudo` ("substitute user, do" — though the popular reading is "superuser do") runs a single command with administrator privileges, for the operations a regular user account isn't permitted to perform: installing system-wide software, editing protected configuration files, restarting system services.

It asks for your own account's password as proof you're authorized to use elevated privileges at all — not some separate "root password," which on many modern systems doesn't even exist as a usable login. Crucially, `sudo` elevates just the one command that follows it; your shell itself stays as your regular user afterward, which is the source of a common beginner mix-up when someone expects the *next* command to also run with elevated permissions.

Because of how much damage a mistyped command can do with full system privileges, it's worth reading a command twice before prefixing it with `sudo` — the same caution that applies to `rm -rf` applies even more once root access removes the usual permission safety net.
