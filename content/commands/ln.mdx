`ln` creates a link — typically a symbolic link (`-s`), which is essentially a small file that points to another path, similar to a shortcut. Opening the symlink transparently opens whatever it points to, which makes it useful for keeping a stable, convenient path to something that lives somewhere less convenient.

Without `-s`, `ln` creates a "hard link" instead, a different and much rarer concept — both names point to the exact same underlying data on disk, with neither considered the "original." Almost all everyday use of `ln` is the symbolic form; the unqualified hard link is a lower-level filesystem detail most people never actually need to reach for.

Because a symlink is just a path reference, it doesn't notice or care if its target later moves or gets deleted — it simply becomes a "broken" link, which is worth checking for if something that used to work suddenly can't find its target file.
