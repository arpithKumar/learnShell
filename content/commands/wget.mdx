`wget` exists for one core job: downloading files, and it handles that
job with a few conveniences that `curl` doesn't bother with by default.
It automatically retries on a flaky connection, can resume an
interrupted download from where it stopped with `-c`, and can
recursively mirror an entire website or directory structure with `-r`.

For straightforward one-off API calls, most people still reach for
`curl`, since it has become the de facto standard for that. But for
"reliably download this exact file, and don't lose progress if my
connection drops," `wget` is purpose-built for the job in a way `curl`
technically can also do, but with more manual flag-juggling.

By default `wget` saves the downloaded file using the name from the
URL itself. The `-O` flag overrides that, letting you choose the saved
filename directly — useful when a URL's final path segment isn't a
sensible filename on its own (a common situation with install scripts
served from a generic endpoint).
