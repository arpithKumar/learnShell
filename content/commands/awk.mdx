`awk` is, technically, a complete programming language — but almost
everyone uses it the same simplified way: as a more capable version of
`cut`, processing input column by column. Every line is automatically
split into numbered fields (`$1`, `$2`, and so on), with `$0` referring
to the entire line, which turns tasks like "print column 2, but only
where column 3 is over 100" into a single line of code instead of a
script.

The basic shape is `awk 'PATTERN { ACTION }' file`. The pattern is
optional — leave it out and the action runs on every line. With a
pattern, the action only runs on lines where that condition is true,
which is what makes `awk '$3 > 100 {print $1}'` work: for every line
where field 3 exceeds 100, print field 1.

Unlike `cut`, which only knows how to slice columns, `awk` can compute,
compare, and aggregate as it goes — keeping running totals, formatting
output, combining multiple fields into a new value. That extra power is
exactly why it's considered a step up in complexity from `grep`, `sed`,
or `cut`: it rewards investment, but there's a real learning curve
between "useful one-liner" and "comfortable with the language."
