When you start a command with `&` at the end, like `npm run dev &`, it
runs in the background and your shell hands the prompt right back to
you instead of waiting for it to finish. `jobs` lists every background
or paused process tied to your current shell session, each tagged with
a small reference number.

That number — shown as `[1]`, `[2]`, and so on — is the same identifier
`bg` and `fg` use to refer back to a specific job, written as `%1`,
`%2`. So a typical sequence looks like: start something in the
background, check `jobs` to confirm it's running and see its number,
then later use `fg %1` to bring it back to the foreground if you need
to interact with it directly.

Job tracking is local to one shell session — close that terminal tab,
and its job list goes with it (the process itself may or may not
survive, depending on whether it was started with `nohup` or similar).
