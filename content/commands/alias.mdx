`alias` lets you define a shorter name for a command you find yourself
typing often. The classic examples are things like `alias ll='ls -lah'`
or `alias gs='git status'` — both save real keystrokes on commands used
dozens of times a day.

Typed directly at the prompt, an alias exists only for that one
terminal session; close the window, and it's gone. To have your
shortcuts available automatically every time you open a new terminal,
the alias definitions need to live in your shell's startup file instead
— typically `~/.zshrc` for zsh or `~/.bashrc` for bash — so they get
re-run every time a new shell starts.

Aliases are intentionally simple: they're a straight text substitution,
not a function with parameters or logic. For anything more elaborate
than "replace this short name with this fixed command," a shell
function is usually the better tool, while `alias` stays the quick,
low-ceremony option for everyday shortcuts.
