`uniq` removes or counts repeated lines, but with one important catch:
it only looks at lines that are sitting right next to each other. Two
identical lines separated by something different in between are
treated as unrelated, not duplicates.

That's why `uniq` is almost always seen written as `sort file | uniq` —
sorting first guarantees that any duplicate lines end up adjacent to
one another, so `uniq` actually has a chance to catch them. Used on its
own, without a preceding sort, it's easy to get misleadingly "clean"
output that still has duplicates the command never had a chance to see.

Its `-c` flag turns it from a simple deduplicator into a basic counting
tool — prefixing each unique line with how many times it occurred. This
combination, `sort | uniq -c`, is one of the most useful one-liners in
shell scripting for quick frequency analysis: how many times does each
URL, status code, or username show up in a log file?
