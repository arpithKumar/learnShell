Normally, redirecting a command's output to a file (`command > file.txt`) means you no longer see that output on screen. `tee` solves exactly that trade-off: it writes the same input to a file *and* passes it through to standard output unchanged, so you get both at once.

The simplest use is saving a log while still watching it happen live: `some-command | tee output.log` shows you the output as it streams by, while also keeping a permanent copy. It's equally useful in the middle of a longer pipeline, letting you capture an intermediate stage's data for later inspection without interrupting the rest of the pipeline's processing.
