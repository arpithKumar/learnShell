`id` reports a fuller picture of identity than `whoami` — not just the username, but the numeric user ID, primary group, and every group the user belongs to. Since file permissions in Unix are checked against both user and group, this is often the more genuinely useful command when something looks like a permissions problem.

Checking `id` for both yourself and the user that owns a file you can't access is a reasonable first diagnostic step: if neither your user ID nor any of your groups match what the file's permissions actually allow, that's the answer to "why can't I open this."
