`dpkg` is the lower-level tool that `apt` itself is built on, working directly with individual `.deb` package files rather than a configured online repository. The main reason to reach for it directly is having a `.deb` file you downloaded manually — software that isn't in your distribution's standard repositories.

The trade-off for working at this lower level is that `dpkg` doesn't automatically fetch missing dependencies the way `apt` does — if the package you're installing needs something else that isn't already present, `dpkg -i` reports the problem rather than resolving it. Running `sudo apt install -f` afterward is the standard fix, letting `apt` pull in whatever was missing.
