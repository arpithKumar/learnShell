`mv` does two jobs that turn out to be the exact same operation under
the hood: moving a file to a new location, and renaming it. Both are
just `mv SOURCE DEST` — the only difference is whether the destination
path changes the file's folder, its name, or both at once.

Moving `report.csv` into an `./archive/` folder and renaming
`draft.txt` to `final.txt` look like different tasks conceptually, but
to the filesystem they're identical: update where a name points to.
That's also why `mv` is essentially instant even for huge files — unlike
`cp`, it doesn't duplicate any data, it just relabels it (as long as the
source and destination are on the same filesystem/drive).

Because there's no confirmation by default, accidentally moving a file
on top of an existing one with the same name will overwrite it
permanently. If you're scripting a bulk move and want a safety net,
prefer `-n` (never overwrite) or `-i` (ask first) over the bare command.
