`scp` ("secure copy") moves files to or from a remote machine, riding
on the same encrypted connection mechanism as `ssh`. The syntax follows
the familiar `cp SOURCE DEST` shape, except either side of the copy can
be prefixed with `user@host:` to point at a location on a remote server
instead of your local filesystem.

That symmetry is genuinely convenient: `scp file.txt server:~/` uploads
a file, while `scp server:~/file.txt ./` downloads one, using
essentially the same mental model in both directions, just with the
remote path on a different side of the command.

For a single file or a small, one-time copy, `scp` is the simplest tool
for the job. Once you're repeatedly syncing the same folder back and
forth — deploying a build output directory over and over, for instance
— `rsync` becomes the better choice, since it only transfers what's
actually different on each run instead of re-sending everything from
scratch every time.
