While `chmod` controls *what* someone is allowed to do with a file,
`chown` ("change owner") controls *who* that someone actually is. Every
file on a Unix-like system belongs to exactly one user and one group;
`chown` reassigns that ownership.

This matters most on shared servers, where different processes need to
operate with different identities — a web server process running as
`www-data`, for example, and a separate deploy user that uploads new
files. If those files are still owned by the deploy user after upload,
the web server may not have permission to read them, even with
generous `chmod` settings, because ownership and permission are two
separate, complementary systems working together.

Because reassigning a file you own to someone else is something the
system is naturally cautious about, `chown` typically needs `sudo` to
run — you can't just give files away without elevated privileges.
