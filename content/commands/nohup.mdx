Normally, closing a terminal sends a "hang up" signal to every process
you started inside it, which causes them to stop too. `nohup` ("no hang
up") tells a command to ignore that specific signal, so it keeps
running in the background even after you log out, disconnect an SSH
session, or close the terminal window entirely.

The classic use case is kicking off a long-running task on a remote
server over SSH and then disconnecting without waiting for it to
finish — without `nohup`, closing that SSH connection would normally
kill the job along with it.

`nohup` is a fairly narrow tool, though: it solves exactly the "survive
terminal closure" problem and nothing more. If you also want to be able
to reconnect later and watch the job's live output, interact with it,
or restart it after a crash, a persistent terminal multiplexer like
`tmux` or `screen` covers more ground than `nohup` alone.
