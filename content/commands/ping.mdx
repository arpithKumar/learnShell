`ping` sends small packets to a remote host and measures how long they
take to come back, making it the fastest first check when something
"isn't working": is the network even reaching this host at all? A
handful of quick, successful replies generally means the network path
itself is fine, and any remaining problem is further up the stack — in
the application, a specific port, or a firewall rule rather than basic
connectivity.

By default `ping` keeps running forever, printing a new result line
every second until you stop it — which is exactly why scripts almost
always pass `-c` to cap it at a fixed number of attempts, so the script
doesn't hang waiting for a command that was never going to stop on its
own.

A genuinely useful diagnostic trick: if pinging a domain name fails but
pinging its numeric IP address succeeds, the issue is almost certainly
DNS resolution rather than the network connection itself — a distinct
and much narrower problem to chase down.
