`ssh` ("secure shell") opens an encrypted connection to a remote
machine and gives you an interactive login as if you were sitting in
front of it directly. It's foundational to remote server work — nearly
every cloud provider, hosting platform, and self-managed server expects
SSH as the primary way to administer it.

Beyond a plain interactive login, `ssh` can also run a single command
on the remote machine and return immediately, without leaving you
logged in: `ssh alice@example.com 'ls -la'` connects, runs `ls -la`
remotely, prints the output, and disconnects, all in one step — handy
for scripts that need to check or trigger something on a remote
machine without a full session.

Authentication can use either a password or a key pair (a private key
you keep locally and a public key installed on the server). Key-based
login is both more convenient — no typing a password every time — and
considered more secure, which is why most production environments
disable password login entirely and require a key. `scp` and `rsync`
both build directly on the same underlying SSH connection for secure
file transfer.
