`crontab` schedules commands to run automatically at fixed times — every night at 2 AM, every Monday morning, every five minutes — without anyone needing to trigger them manually. It's the standard way recurring tasks like backups, cleanup scripts, or scheduled reports get automated on Unix-like systems.

Each scheduled line has five time fields followed by the command to run: minute, hour, day of month, month, and day of week, each either a specific value, a range, or `*` meaning "any." `0 2 * * *` reads as "at minute 0 of hour 2, every day" — once daily at 2 AM.

The most common source of "it works when I run it manually but not under cron" confusion is environment: cron jobs run with a far more minimal environment than an interactive shell, often missing `PATH` customizations or assuming a different working directory. Scripts intended to run under cron should generally use full, explicit paths rather than relying on anything from a normal interactive session.
