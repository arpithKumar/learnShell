`pkill` finds processes by name and sends them a signal — by default, the same polite `SIGTERM` that plain `kill` sends — without needing to look up a process ID first. It collapses the common two-step "find the PID, then kill it" workflow into one command.

The trade-off for that convenience is precision: `pkill` matches by name pattern, so if more than one process shares that name, all of them get signaled, not just the one you meant. Running `pgrep` first (the read-only counterpart that just lists matches) is a safer way to confirm exactly what `pkill` would affect before actually running it.
