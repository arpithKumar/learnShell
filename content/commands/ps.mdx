`ps` ("process status") lists what's currently running on your system
right now, including each process's ID (its PID) — information you'll
need any time you want to stop, inspect, or otherwise interact with
that specific process later, often with `kill`.

The combination almost everyone learns is `ps aux | grep SOMETHING`:
list every process from every user, in detailed form, then filter that
list down to lines matching a name you're looking for. It's a quick
way to answer "is this program actually running, and what's its PID?"
without needing a graphical task manager.

Because `ps` only captures a single moment in time, it's a poor fit for
watching resource usage change — a process that's idle right now might
spike a second later, and `ps` alone won't show you that. For ongoing
monitoring, `top` (or a more modern equivalent like `htop`) gives you
the same kind of information, but continuously refreshed.
