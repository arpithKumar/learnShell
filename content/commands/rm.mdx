`rm` deletes files, and it does so immediately and permanently — there's
no recycle bin to recover from. On its own, plain `rm` only removes
regular files; trying to delete a directory without `-r` fails on
purpose, since a directory might contain other files and folders that
all need to be accounted for too.

Combined with `-f` (force), `rm -rf` becomes one of the most powerful —
and most dangerous — commands you'll use in a shell. It deletes a
folder and everything inside it, suppresses any "are you sure"
prompts, and won't even complain if some of the targets don't exist.
That combination is genuinely necessary sometimes (clearing out a build
folder, for instance), but it's worth building real caution around it
before typing it on autopilot.

A good habit for beginners: practice with plain `rm` and `rm -i` first,
and only reach for `-rf` once you're confident reading and double
checking a path before you hit enter. The classic disaster scenario is
a stray space turning `rm -rf ./build` into something that deletes far
more than intended — always read the line back before running it.
