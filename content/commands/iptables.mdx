`iptables` configures the Linux kernel's built-in firewall, controlling which network traffic is allowed in, out, or forwarded through the machine. It's powerful and precise, but also unforgiving — rules are evaluated in order, and a wrong one can block traffic you didn't intend to, including the very SSH connection you're using to manage the server.

The mental model is "chains" of rules: `INPUT` for incoming traffic, `OUTPUT` for outgoing, `FORWARD` for traffic passing through. Each rule specifies what to match (a protocol, a port, a source) and what to do when it matches (`ACCEPT`, `DROP`, `REJECT`). Newer tools like `nftables` and `ufw` (a simpler front-end) have become more common on recent distributions, but `iptables` remains widely deployed and worth understanding directly.
