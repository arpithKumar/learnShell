`exec` replaces the currently running shell process with whatever command you give it, rather than launching that command as a new child process. The original shell is gone — there's no "coming back" to it, because it no longer exists; the new command has taken over its process ID entirely.

This sounds destructive, and used directly it usually is exactly that intentional — `exec bash` swaps your current shell for a fresh one, useful after a major environment change. The more common everyday use, though, is `exec` without a command, just redirecting: `exec > logfile.txt` redirects all of a script's subsequent output to a file in one line, instead of adding `>> logfile.txt` to every single command.

Because it replaces rather than spawns, any code written after a bare `exec COMMAND` in a script is unreachable — the script's own process has been entirely replaced before reaching that point.
