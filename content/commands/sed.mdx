`sed` ("stream editor") processes text one line at a time, applying a
small built-in scripting language to transform it as it goes — without
ever opening an interactive editor. The overwhelming majority of real
`sed` usage boils down to one pattern: `sed 's/find/replace/g'`,
substituting every occurrence of "find" with "replace" across a stream
of text or a file.

The syntax `s/pattern/replacement/flags` is worth memorizing as a unit:
`s` for substitute, the pattern and replacement separated by a
delimiter (conventionally `/`, though any character works), and
optional trailing flags — `g` for "global," meaning replace every match
on a line, not just the first one. Leaving off `g` is the single most
common reason a `sed` substitution seems to only "half work."

By default `sed` prints its transformed output to the terminal without
touching the original file, which is a safe way to preview a change.
Adding `-i` switches it to editing the file directly, in place — a
genuinely destructive operation with no built-in undo, so it's good
practice to run the command without `-i` first, confirm the output
looks right, and only then add `-i` to commit the change for real.
