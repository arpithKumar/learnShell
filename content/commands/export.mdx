By default, a variable you set in your shell — `NAME=VALUE`, with no
`export` — is purely local to that shell. Any program you run from it
can't see it, because environment variables are only passed down to
*child* processes, and a plain shell variable was never promoted into
that environment in the first place.

`export` is exactly that promotion. Once a variable is exported, every
program your shell launches afterward — scripts, other command-line
tools, whole applications — inherits its own copy of it. This is the
mechanism behind configuration patterns like `NODE_ENV`: setting and
exporting it in your shell makes it visible to any Node.js process you
then start from that same shell.

Because the effect only lasts for the current session by default,
anything you want available every time you open a new terminal needs to
be added to your shell's startup configuration file instead of typed
fresh each session.
