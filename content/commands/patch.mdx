`patch` takes a diff — a structured description of line changes, typically produced by `diff -u` — and applies those changes to a target file. Together, `diff` and `patch` form a complete pair: one describes a change, the other applies it, which is exactly how patches were shared and applied to source code for decades before centralized version control made it less central to everyday workflows.

`-p` controls how much of the file path inside the patch gets stripped before matching against your local files, which matters when a patch was generated in a different directory structure than the one you're applying it to. `-R` runs the same patch in reverse, undoing a change that was already applied — useful for backing out something that turned out to be wrong.
