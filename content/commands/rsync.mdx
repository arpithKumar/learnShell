`rsync` ("remote sync") copies files the way `cp` or `scp` do, but with
one crucial difference: on repeated runs, it only transfers the parts
of files that actually changed since the last sync, rather than
re-sending everything from scratch every time. That difference makes
it dramatically faster for backups, deployments, and keeping two
folders in sync, whether that's locally on one machine or across a
network via SSH.

The flag combination almost everyone uses is `-a` ("archive" mode),
which bundles together recursion, permission preservation, timestamp
preservation, and symlink handling into one sensible default — it's
rarely worth setting those individually when `-a` already covers the
common case correctly.

`rsync` is also one of the few commands where a single character — that
trailing slash on the source path — changes the entire outcome of the
command. It's genuinely worth pausing and double-checking before
running any `rsync` command for real, especially one using `--delete`,
which can permanently remove files at the destination if the source and
destination are reversed by mistake. `--dry-run` exists specifically to
let you preview the exact changes before committing to them.
