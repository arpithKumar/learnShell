Every running process has access to a set of environment variables —
key/value pairs like `PATH` and `HOME` that programs read to know how
to behave. `env` shows you that full list as it currently stands for
your shell, which makes it a useful first stop when debugging
configuration that depends on an environment variable being set
correctly.

Its second job — prefixing a command with one or more `NAME=VALUE`
pairs — runs that single command with those variables temporarily
overridden, without changing anything about your ongoing shell session.
`env NODE_ENV=production node server.js` is a common pattern for testing
how an application behaves under a different configuration, just for
that one run, while your terminal's actual environment stays untouched.

This is distinct from `export`, which *does* persist a variable for the
rest of your current shell session (and anything it launches
afterward) rather than just one command.
