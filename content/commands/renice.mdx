`renice` adjusts the scheduling priority of a process that's already running, using the same niceness scale as `nice` (-20 highest priority, 19 lowest). Where `nice` sets a starting priority when a command first launches, `renice` is for the moment you realize, after the fact, that something already running needs to back off.

The common scenario: `top` or `ps` reveals a process eating far more CPU than expected, and rather than killing it outright, `renice -n 19 -p PID` lets it keep running while yielding CPU time to everything else — a gentler intervention than `kill` when the process is still doing useful work, just too aggressively.
