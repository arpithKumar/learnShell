`find` walks a directory tree and filters what it finds by name, type,
size, age, permissions, and more — it's the general-purpose answer to
"where is this file" or "which files match this condition," when a
simple `ls` isn't precise enough.

The expression syntax takes some getting used to: instead of flags
controlling *how* find behaves, most of them are filters that combine
together, left to right, like a sentence. `find . -name '*.ts' -type f`
reads almost literally as "starting here, find things named *.ts that
are regular files." Quoting the pattern matters — without quotes, your
shell would try to expand `*.ts` itself before `find` ever sees it,
which usually isn't what you want.

`find`'s real power shows up when you act on the results, either by
piping into another command (often via `xargs`) or using `-exec`
directly. Both let you run a command against every match — deleting old
log files, batch-renaming, or running a script against a filtered set
of files. Because that action can be destructive, the safe workflow is
always: run the `find` expression alone first, confirm the matches look
right, *then* add the `-delete` or `-exec` part.
