`file` looks at a file's actual content — not its name or extension — and reports what kind of file it really is: a JPEG image, a gzip archive, a plain text file, an executable. This matters because a file extension is just a naming convention; nothing stops a `.txt` file from actually containing binary data, or a downloaded file from having no extension at all.

It's most useful exactly in that situation: a file with a missing, generic, or untrustworthy extension, where you need to know what you're actually dealing with before opening or processing it. `file -i` gives the same answer as a formal MIME type instead of a plain description, which is sometimes the more useful form for scripting.
