`type` tells you what a given command name actually resolves to: a shell builtin like `cd`, an alias you defined, a function, or an executable file somewhere on your `PATH`. It's the most complete answer to "what actually happens when I run this," more thorough than `which`, which only checks for files on disk.

This matters because the same name can mean different things depending on what's defined where — `ls` might be a plain binary on one system and an alias adding color flags on another. `type -a` shows every definition that exists for a name, in the order the shell would actually try them, which is the real answer when more than one thing could match.
