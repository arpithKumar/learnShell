`du` ("disk usage") tells you how much space files and folders actually
take up on disk — the classic scenario is wondering why a project's
`node_modules` folder has suddenly ballooned, or why a drive is running
low on space and you need to find what's responsible.

The command everyone reaches for first is `du -sh ./some-folder`:
summarized (`-s`, just the total, not every nested subfolder) and
human-readable (`-h`, so you see "482M" instead of a raw byte count).
Without `-s`, `du` recursively prints a size for *every* subdirectory it
walks through, which is rarely what you want when you're just trying to
answer "how big is this folder, total?"

For hunting down what's actually using the space inside a folder, a
common pattern is `du -sh * | sort -rh` — list each item's size, then
sort by size descending, so the biggest offenders show up first instead
of you scanning a long unsorted list by eye.
