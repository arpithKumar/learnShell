`tr` ("translate") performs simple, character-by-character
substitution or deletion: every character that appears in SET1 gets
replaced by the character in the same position in SET2. It's much more
limited than `sed`, which can match whole patterns, but for quick jobs —
uppercasing text, stripping a specific character, collapsing repeated
spaces — it's often faster to type than reaching for a heavier tool.

A defining quirk is that `tr` only reads from standard input, never
directly from a file path. That means you'll usually see it at the end
of a pipe (`cat file | tr ...`) or paired with input redirection
(`tr ... < file.txt`), rather than written as `tr ... file.txt` the way
most other text tools accept a filename argument.

Character classes like `[:punct:]`, `[:digit:]`, and `[:alpha:]` let you
target whole categories of characters without spelling each one out,
which keeps `tr` commands readable even when the set of characters
you're targeting is large.
