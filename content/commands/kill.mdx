`kill` sends a signal to a running process, identified by its PID. The
name is a little misleading: by default it sends `SIGTERM`, which is
better understood as a polite request to shut down than a forced
termination — a well-written program can catch that signal and use it
as a cue to clean up (closing files, finishing in-flight work) before
actually exiting.

`kill -9` is the genuinely forceful version, sending `SIGKILL` instead.
The operating system enforces this one immediately and unconditionally
— the target process gets no chance to clean up or respond at all. It's
the right tool when a process is unresponsive and a normal `kill`
hasn't worked after giving it a moment, but it should generally be a
fallback, not a first move, since skipping a program's cleanup logic
can occasionally leave things in an inconsistent state (an unfinished
write to a file, for example).

Between those two extremes, Unix systems support a whole range of
named signals (`kill -l` lists them) for more specific situations, but
`SIGTERM` and `SIGKILL` cover the overwhelming majority of everyday
use.
